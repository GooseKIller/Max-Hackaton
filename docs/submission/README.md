# Готовность к сдаче

Для онлайн-этапа выбран чат-бот: https://max.ru/t179_hakaton_max_bot.
Публикация мини-приложения и собственного API в этот вариант не входит.

## В репозитории

- Бот, адаптивный UI, API планов, отдельный worker напоминаний.
- Согласие/отказ в диалоге, рабочие маршруты кнопок напоминания.
- Защита webhook, подтверждение callbacks, журнал повторной доставки.
- Docker, Compose, необязательный HTTPS-профиль, закреплённые зависимости.
- OpenAPI и DATA-API для отдельного варианта с API. `api_base_url` и `team_id` пока null,
  чтобы не выдавать localhost или вымышленный адрес за проверяемый сервис.
- Статус проверок: [verification.md](verification.md).

## Внешние шаги, которые нельзя отметить сделанными по локальным тестам

1. Согласовать с Антоном версию работающего бота и его доступность на время проверки.
2. Проверить конечный путь в mobile и web MAX, реальную доставку напоминания.
3. Зафиксировать исходники после согласования версии. После дедлайна не менять.

Живой каталог не обязателен по заданию при честной маркировке демо. Поэтому
отсутствие ключа PRO.Культура.РФ не блокирует сдачу. Не обещаем покупку билетов
на синтетических событиях, рост фактических трат или результаты не проведённых интервью.

Команда может провести пять наблюдаемых прохождений сценария уже сейчас, с вымышленным
остатком 3000. Протокол и вопросы: [validation.md](../research/validation.md).
Фиксировать время, ошибки, приемлемость результата и прямые замечания; не заменять
это мнением разработчиков или синтетическими пользователями.
