# Готовность к сдаче

Эта папка содержит материалы для команды, а не подтверждение завершённого публичного
развёртывания. Перед отправкой организаторам нужны реальные адрес и данные команды.

## В репозитории

- Бот, адаптивный UI, API планов, отдельный worker напоминаний.
- Согласие/отказ в диалоге, рабочие маршруты кнопок напоминания.
- Защита webhook, подтверждение callbacks, журнал повторной доставки.
- Docker, Compose, необязательный HTTPS-профиль, закреплённые зависимости.
- OpenAPI и DATA-API с проверочными запросами. `api_base_url` и `team_id` пока null,
  чтобы не выдавать localhost или вымышленный адрес за проверяемый сервис.
- Статус проверок: [verification.md](verification.md).
- [Презентация для команды, PDF](presentation-review.pdf) и
  [редактируемый PowerPoint](presentation-review.pptx), 11 слайдов.
  Это версия для согласования, не финальная сдача: на техническом слайде ещё нужно
  указать реальный HTTPS-адрес, финальный commit hash и конкурсное название команды.
  Текст слайдов: [presentation.json](presentation.json).

## Внешние шаги, которые нельзя отметить сделанными по локальным тестам

1. Получить бесплатное размещение или согласовать с организаторами иной вариант.
2. Согласовать с Антоном переключение работающего бота на выбранный commit.
3. Подключить HTTPS мини-приложение через форму из письма.
4. Проверить конечный путь в mobile и web MAX, реальную доставку напоминания.
5. Добавить точное имя/ID команды, реальный адрес API, финальный commit hash.
6. Передать секреты только через закрытый канал сдачи, не в публичном GitHub/PDF.
7. Зафиксировать исходники после согласования версии. После дедлайна не менять.

Живой каталог не обязателен по заданию при честной маркировке демо. Поэтому
отсутствие ключа PRO.Культура.РФ не блокирует сдачу. Не обещаем покупку билетов
на синтетических событиях, рост фактических трат или результаты не проведённых интервью.

Команда может провести пять наблюдаемых прохождений сценария уже сейчас, с вымышленным
остатком 3000. Протокол и вопросы: [validation.md](../research/validation.md).
Фиксировать время, ошибки, приемлемость результата и прямые замечания; не заменять
это мнением разработчиков или синтетическими пользователями.
