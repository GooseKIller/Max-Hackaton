## The letter

**Тема:** Запрос ключа API «PRO.Культура.РФ» — события «Пушкинской карты», Республика Татарстан

Здравствуйте!

Меня зовут [ИМЯ ФАМИЛИЯ], я участник команды «[НАЗВАНИЕ КОМАНДЫ]» хакатона
[НАЗВАНИЕ ХАКАТОНА] ([ОРГАНИЗАТОР]), финал которого проходит 29 октября в Казани.

Мы разрабатываем сервис в мессенджере MAX, который помогает подросткам 14–22 лет
подбирать мероприятия под «Пушкинскую карту». Задача, которую мы решаем: по нашим
замерам, только по Казани в программе доступно около 1100 мероприятий, при этом
существующие афиши выводят их простым хронологическим списком, без учёта возраста
пользователя, его свободного времени и остатка на карте. В результате школьник видит
в одной ленте спектакли для дошкольников и мероприятия для организованных школьных
групп в будни утром, а действительно подходящие ему события теряются.

Мы хотим строить сервис на первоисточнике, а не на агрегаторах, поэтому обращаемся
за ключом доступа к API «PRO.Культура.РФ».

**Что нам нужно:**

- метод `GET /api/2.5/pushkinsCardEvents`, а также справочные `/locales`,
  `/categories`, `/organizations`;
- только чтение, без записи;
- географический охват: Республика Татарстан (при возможности — вся Россия, для
  проверки переносимости решения на другие регионы);
- ожидаемая нагрузка: несколько сотен запросов в сутки, с кэшированием на нашей
  стороне и соблюдением ограничения в 100 объектов на запрос.

**Как мы планируем использовать данные:**

- данные используются только для подбора и отображения мероприятий конечному
  пользователю, с прямым переходом на официальную ссылку покупки билета
  (поле `saleLink`);
- мы не перепродаём данные, не передаём их третьим лицам и не предоставляем
  собственный платный доступ к ним;
- в интерфейсе указывается источник данных — «PRO.Культура.РФ» — и дата
  актуальности выгрузки;
- мы не изменяем содержание мероприятий и не добавляем к ним собственных оценок,
  выдавая их за официальные.

Если оформление полноценного партнёрства для студенческой команды невозможно или
требует длительного согласования, будем признательны за любой из облегчённых
вариантов:

1. временный ключ с ограниченным сроком действия — до конца хакатона;
2. тестовый ключ с ограничением по числу запросов;
3. разовая выгрузка мероприятий «Пушкинской карты» по Республике Татарстан в JSON.

Любого из них достаточно, чтобы мы построили прототип на реальных данных, а не на
синтетических. Нам важно не имитировать интеграцию: если доступа к реальным данным не
будет, мы обязаны будем указать в материалах проекта, что используем подготовленные
тестовые данные.

Готовы подписать необходимые документы, согласовать условия использования и указать
источник данных в любой форме, которую вы сочтёте правильной. Также готовы показать
работающий прототип до финала и обсудить дальнейшее развитие сервиса.

Буду благодарен за ответ. Если удобнее обсудить голосом — [ТЕЛЕФОН].

## In parallel — the second, independent route

The Ministry of Culture open data portal publishes the same PRO.Культура.РФ events as
dataset `7705851331-events`. Its key is requested through a self-service form and,
according to the portal, is emailed back shortly.

Submit that form the same day: <https://opendata.mkrf.ru/item/dev>

It is a different gatekeeper with a much lower bar, and it may well arrive first. The
data is the same source, refreshed weekly rather than live — good enough to build and
demo against while the partnership request is being processed.

## If neither key arrives

Fall back to a frozen snapshot of real Kazan events, keep the data layer behind one
interface so the source is swappable, and **state plainly in the README and the
presentation** that the integration is modelled, along with what is needed to make it
real. The brief explicitly requires this and explicitly warns against faking an
integration.
