# Развёртывание и проверка в MAX

28 сентября 2026. Бот работает через polling. Для этого режима новый хостинг,
домен и публичный HTTPS не нужны. Перезапуск согласуйте с командой,
чтобы не запускать второго получателя событий.

## Стоимость и правила

Работающий процесс polling должен оставаться запущенным с доступом к MAX.
Сон компьютера или потеря сети прервут ответы. HTTPS нужен при выборе webhook
или публикации собственного API/мини-приложения; это отдельный вариант ниже.
Никаких расходов эта инструкция не требует.

## Локальная проверка

Для запуска бота и напоминаний одной командой из корня репозитория:

```bash
docker compose -f compose.polling.yaml up -d --build
```

Этот файл запускается самостоятельно, без `compose.yaml` и HTTPS-профиля.
Он не открывает порты и не регистрирует webhook. Остановка и повторный запуск:
`docker compose -f compose.polling.yaml stop` и `docker compose -f compose.polling.yaml start`.
Не добавляйте `down -v`: эта команда удаляет сохранённые профили и историю.

Без Docker можно запустить polling отдельно:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r backend/requirements.txt
python backend/runner.py
```

До запуска заполните закрытые параметры в `.env` по [примеру](../.env.example);
существующий файл команды сохраняйте. `.env` загружается автоматически.
Прежний polling команды должен быть остановлен по согласованию до запуска нового.
При переходе с Python на Docker сохраните прежнюю SQLite через backup API и
перенесите копию в `/srv/state/app.db` тома `bot-state` до первого запуска.
Не копируйте один `.db` у работающей WAL-базы и не заменяйте существующую базу без
резервной копии. Без переноса Docker начнёт с пустой базы.
После запуска проверьте прежний профиль и новый диалог; не запускайте старый процесс
параллельно. Компьютер должен оставаться включённым на всё время проверки.

Для проверки решения целиком (API, UI и polling бота): `docker compose up -d --build`, затем
`python backend/verify_api.py http://localhost:8000`. Compose запускает uvicorn,
но не polling. Перед обновлением рабочей
базы сделайте резервную копию через SQLite backup API; не копируйте только основной
файл у работающей WAL-базы. Учитывайте, что копия тоже содержит пользовательские данные.

## Необязательно: HTTPS, мини-приложение и webhook

1. Согласовать с Антоном остановку старого polling. У одного бота должен быть один
   активный получатель. Регистрация webhook отключает polling на стороне MAX.
2. Получить выбранный commit на сервере. Для HTTPS нужны DNS, открытые 80/443,
   действующий сертификат. Адрес и сервер может предоставить университет/организатор.
3. Заполнить закрытые параметры `.env` по [примеру](../.env.example),
   а также `MAX_WEBHOOK_SECRET` и `APP_DOMAIN`.
   Секрет: `python -c 'import os; print(os.urandom(32).hex())'`.
   Не публиковать значение. `MINI_APP_BOT` пока оставить пустым.
4. Запустить:

```bash
docker compose -f compose.yaml -f compose.https.yaml --profile live up -d --build
```

Команда запускает API/UI, worker напоминаний и Caddy. Тома сохраняют базу и сертификаты.
Если HTTPS уже предоставляет организатор, Caddy не нужен: проксировать его адрес
на сервис `bot:8000`, использовать `docker compose --profile live up -d --build`.
Ограничить размер запросов на внешнем прокси до 64 KB. Настроить rate limit под
нагрузку пилота: локальные тесты не являются проверкой устойчивости к DDoS.

5. Проверить: `python backend/verify_api.py https://ВАШ-ДОМЕН`.
6. После согласованной остановки polling зарегистрировать webhook:

```bash
python backend/register_webhook.py https://ВАШ-ДОМЕН/webhook --confirm-switch
```

Секрет берётся из `.env`. Подписка: `bot_started`, `message_created`, `message_callback`.
Сам запуск сервера подписку не меняет. Один процесс uvicorn, без нескольких workers.

7. Если нужно мини-приложение, передать `https://ВАШ-ДОМЕН/app/` через форму организаторов:
   https://sbor-ssylok-dlya-mini-prilojeniy.testograf.ru/.
   После подтверждения заполнить `MINI_APP_BOT=t179_hakaton_max_bot`, пересоздать
   сервис bot той же командой Compose. Только тогда появится кнопка `open_app`.
8. Пройти сценарий ниже в мобильном и веб-MAX, записать версии клиентов и результаты.
9. Если публикуется API, экспортировать его описание с реальным адресом:
   `python backend/export_api.py --base-url https://ВАШ-ДОМЕН`.
   В DATA-API заполнить team_id. Формат составлен по полям задания, а не по неизвестной
   схеме проверяющей платформы; сверить с образцом организаторов, если его предоставят.

## Финальная проверка

- Новый пользователь: старт, возраст, остаток, карточка, реакция, план.
- Изменение остатка, неизвестный кино-лимит, ноль, ошибочный ввод.
- Если подключено мини-приложение: открытие, расчёт, детали, закрытие, возврат в чат.
- `/reminders`: выключены по умолчанию; включение и отключение подтверждаются.
- Preview будущего расписания без отправки:
  `python -m backend.app.reminder_worker --once --dry-run --preview-at 2026-12-17T12:00:00+03:00`.
- Реальную доставку проверить отдельно с согласившимся тестировщиком. Preview не
  считается доставкой. Не меняйте системные часы и не отправляйте массовые тесты.
- Перезапуск сохраняет профиль, текущую карточку и реакцию на неё.
- Если включён webhook: повтор не создаёт повторную реакцию; неверный секрет даёт 403.
- Если опубликован API: `/health` не раскрывает путь базы, статистику пользователей или их данные.
- Вписать фактические результаты в `docs/submission/verification.md`.

## Границы

Polling повторяет неудачную отправку до трёх раз, затем продолжает работу с другими
сообщениями. Сохранённый ответ не помечается доставленным, но отдельной очереди
для его последующей автоматической отправки пока нет. Ошибки видны в логах.

Webhook обрабатывается вне event loop. Обработчик диалога последовательный;
если занят, возвращаем 503 для повторной доставки MAX. Ответ и профиль сохраняются
транзакционно до отправки. Сбой после принятия сообщения MAX, но до записи успеха,
может дать повтор ответа. Для нагрузки выше пилота нужны очередь и серверная БД.

Бот и UI не синхронизируют профиль: API расчёта stateless, `initData` не используется
для доступа к данным. Перед добавлением синхронизации обязательно проверить подпись
MAX на сервере. ID из URL или `initDataUnsafe` не является авторизацией.
